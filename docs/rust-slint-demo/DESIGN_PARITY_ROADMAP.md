# Roadmap for porting the existing Photo Culler design to Slint

**Design requirement.** Recreate the Photo Culler interface already in use. Keep the original screen structure, dark palette, typography, spacing, controls, labels and interaction patterns for each surface. Slint implements the views in one codebase. Native and web can compose those views differently where their existing references differ.

**Reference baseline.** Start with commit [`3701bed`](https://github.com/scherenhaenden/photo-culler/commit/3701bedf924bc3a3927166ef3a86c59d688d1ab3), the current `master` reference for the prior app. Use the native egui client for desktop and the legacy templates and CSS for web. Pin the reference screenshots in UX01 so nobody has to guess which version or state to match. Implementation work starts from the Sprint 01 branch.

Activate it once the corresponding Rust operation is integrated.

## Comparison and handoff

1. Capture legacy and Slint with the same locale, photo set, screen state, viewport, scale and zoom. On desktop crop the OS-owned window frame when comparing client layouts. Record platform-specific frame or file-dialog differences separately.
2. Compare screen structure first, then component geometry, type, color/state, icon placement, photo crop and text. Store paired images and, where useful, an overlay. Sample colors inside solid regions so font antialiasing does not change the result. Use the same data for screenshots even when the integrated demo has a smaller fixture.
3. Check the original interactions against the port, including focus order, selection, arrows, filters and the view transitions available on that surface. Record absent backend support separately from a missing visual element or a behavior regression.
4. Record each difference with screen, surface, severity, reference, actual result and fix or approval. Treat layout, palette role, missing control, broken action and image placement differences as open until addressed or explicitly approved. Record harmless platform rendering differences in the sign-off. Avoid a blanket pixel-diff tolerance that could hide a layout change.
5. Keep layout and style PRs in their assigned Slint UI paths. Have the D34 integrator own root view selection, shared controller registration and packaging. Link the reference and comparison from each visual PR. The acceptance record identifies the exact candidate commit.
