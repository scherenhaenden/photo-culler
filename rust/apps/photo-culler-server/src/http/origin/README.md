# Tarea 11: integración pendiente

La base a68f360 no contiene `photo-culler-server`, el arnés común ni contratos Axum. `mod.rs` es un módulo Rust autónomo sin dependencias; su router de pruebas es un doble, no un servidor HTTP real. Prueba: `rustc --edition=2021 --test rust/apps/photo-culler-server/src/http/origin/mod.rs -o /tmp/photo-culler-origin-tests && /tmp/photo-culler-origin-tests`.

El integrador debe registrar este módulo y un middleware antes de **todas** las rutas y de cualquier efecto lateral. Construir `OriginPolicy` a partir de un origen público configurado explícitamente y el puerto real asignado; no usar Host, Forwarded ni X-Forwarded-* para configurarlo. Por defecto enlazar `default_bind_address()`; LAN requiere configuración explícita y autorización propia. La política admite un único origen canónico con puerto explícito; para URLs que omiten puertos por defecto el adaptador debe establecer una representación canónica segura y coherente antes de la comparación, sin aceptar listas, userinfo ni ambigüedades. Una configuración con varios nombres o proxy necesita contrato y pruebas adicionales.

Pasar todos los valores crudos de Host, Origin y Sec-Fetch-Site, sin concatenarlos ni descartar duplicados; rechazar valores no ASCII o que el servidor no pueda representar. El adaptador deberá rechazar cabeceras duplicadas antes de cualquier normalización y proporcionar la autoridad HTTP/2 validada como Host único, rechazando discrepancias entre `:authority` y Host. Rechazar los fallos con 403 sin CORS permisivo. Aplicar la política también a errores, recursos estáticos y preflight; no habilitar CORS cruzado. OPTIONS no autoriza una operación posterior.

Firefox 135 manda `Origin: null` en el POST WASM same-origin de `/api/v1/session/pair`. El adaptador admite esa combinación solo para esa ruta, con un `Host` que coincide exactamente con el origen configurado y `Sec-Fetch-Site: same-origin`. No se admite para pairing-code issuance ni ninguna otra mutación; `cross-site` sigue rechazado.

`native_authenticated` solo puede ser verdadero después de verificar una credencial de cliente nativo resistente a CSRF, transmitida fuera de cookies y no accesible a páginas web ajenas; jamás inferirlo de un header aportado por el cliente, la ausencia de Origin o una cookie. El middleware puede autenticar esa credencial antes de invocar la política, pero no ejecutar rutas antes de ella. Los permisos por operación siguen siendo responsabilidad de la sesión (tarea 10); esta política no autentica usuarios. Siempre validar un Origin presente aunque el cliente nativo esté autenticado.

Aplicar `frontend_headers` a las respuestas HTML y WASM correspondientes, sustituyendo duplicados; servir JavaScript con su propio MIME correcto y `nosniff`. La CSP debe validarse con el frontend Slint real y adaptarse de forma mínima si requiere otros recursos. Las pruebas actuales comprueban la política y cabeceras sobre un router falso; añadir pruebas de integración Axum, navegador y sesiones cuando estén disponibles.
